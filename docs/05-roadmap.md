### API 소스 결정: 재정경제부_공공기관 채용정보 (확정)

`/detail` 실제 응답 확인 결과, 재정경제부 API가 필요한 필드를 대부분 제공한다. **주 소스로 확정한다.**

| 소스 | 판정 |
|---|---|
| **재정경제부_공공기관 채용정보** | ✅ **주 소스 확정.** 접수시작일·원문URL·NCS직무코드·고용유형·첨부파일 URL·전형절차 텍스트 모두 제공 |
| 인사혁신처_공공취업정보 | ❌ 제외. 목록에 마감일만 있고 접수시작일·직렬·원문URL 없음. 용어 체계가 공무원 중심 |
| 행정안전부_지방공공기관 | ❌ MVP 제외. 상세조회·첨부파일 없음 |

> **재정경제부 API = 잡알리오 = opendata.alio.go.kr는 모두 같은 데이터다.** 첨부파일 URL이 `opendata.alio.go.kr/recruit/downloadAtchFile`인 것으로 확인됨. 별도 소스로 취급하지 않는다.

**필드 매핑**

| 도메인 필드 | API 필드 |
|---|---|
| `INSTITUTION.name` / `external_code` | `instNm` / `pblntInstCd` |
| `RECRUITMENT.title` | `recrutPbancTtl` |
| `RECRUITMENT.apply_start_at` | `pbancBgngYmd` |
| `RECRUITMENT.apply_end_at` | `pbancEndYmd` |
| `RECRUITMENT.source_url` | `srcUrl` |
| `RECRUITMENT.external_id` | `recrutPblntSn` |
| `POSITION.job_category` | `ncsCdLst` / `ncsCdNmLst` (NCS 직무분류코드) |
| `POSITION.headcount` | `recrutNope` |
| `POSITION.work_region` | `workRgnNmLst` |
| `ATTACHMENT.file_url` / `file_name` | `files[].url` / `files[].atchFileNm` |
| (신규) `employment_type` | `hireTypeLst` / `hireTypeNmLst` |
| (추출 입력) | **`scrnprcdrMthdExpln`** — 전형절차 설명 텍스트 |

**수집 시 사용할 `/list` 파라미터 (실호출 검증 완료)**

```
ncsCdLst    = R600020,R600002   # 정보통신, 경영.회계.사무
hireTypeLst = R1010,R1070       # 정규직, 청년인턴(채용형)
ongoingYn   = Y
numOfRows   = 100
pageNo      = 1..N
```

> ⚠️ **`instType`을 넣으면 `totalCount: 0`이 반환된다.** 콤마 다중값 미지원 또는 파라미터명 불일치로 추정. 실호출 결과:
> | 파라미터 | totalCount |
> |---|---|
> | `ongoingYn=Y` 만 | 607 |
> | `+ ncsCdLst + hireTypeLst` | **30** ✅ |
> | `+ instType=A2001,...` | **0** ❌ |
> | `recrutPbancTtl=신입사원` | 363 |
>
> **기관유형 필터는 기관 마스터로 우회한다.** opendata.alio의 **기관정보 오픈API**로 기관 목록과 `instType`을 받아 `INSTITUTION` 테이블에 저장하고, 수집 시 `pblntInstCd`로 조인해 A2005(기타공공기관)를 제외한다. 기관 정보는 거의 변하지 않으므로 주 1회 갱신으로 충분하다.

**확인된 운영 규모: 접수중 공고 30건.** 하루 신규는 수 건 수준이므로 검수 부담과 트래픽 모두 여유롭다.

첨부파일은 `atchFileType`이 `A`(공고문) 또는 `Z`(참고자료)인 것만 다운로드한다. 입사지원서(`B`)·직무기술서(`C`)는 제외한다. `Z`에는 무관한 파일(자기소개서 등)도 섞이므로 파일명 휴리스틱으로 선별한다.

**이 필터 조합으로 일일 1,000건 제한은 실질적 제약이 되지 않는다.** 대상 공고가 크게 줄어들어 백필도 하루에 완료 가능하다. 앞서 우려한 트래픽 분할 실행 로직은 불필요해졌다.

### ✅ W0 검증 결과 (실제 응답 확인 완료)

**`scrnprcdrMthdExpln`에 필기시험 정보가 존재한다.** 한국철도공사 공고 확인:

```
○ 2차(필기시험) : 2배수 선발, 직업기초능력평가(30문항),
   직무수행능력평가(30문항), 철도법령(10문항)
```

| 얻을 수 있는 것 | 얻을 수 없는 것 |
|---|---|
| 필기전형 유무 | **NCS 세부 영역** (의사소통·수리·문제해결 등) |
| 시험 유형 (직업기초능력=NCS / 직무수행능력=전공) | |
| 문항 수, 전형 배수 | |

→ **NCS 영역은 여전히 첨부 공고문 파싱이 필요하다.** 단, 아래 2단 전략으로 파싱 대상이 크게 줄어든다.

### 확정된 수집 흐름

```
① /list 호출 (필터 적용, 100건/회)
② scrnprcdrMthdExpln 으로 필기 유무 1차 판정   ← 대부분 여기서 탈락
③ 필기 있는 공고만 /detail 호출 → files[], steps[] 획득
④ files 중 A(공고문) + Z(참고자료)만 다운로드 → NCS 영역 추출
```

> **`Z`(기타)를 반드시 포함한다.** 철도공사 확인 결과 NCS 세부 영역은 공고문이 아닌 `채용 공고 참고자료.pdf`(타입 `Z`)에 있다. `A`만 받으면 핵심 차별점을 확보할 수 없다.

> **②가 이 설계의 핵심이다.** 필터 적용 전 표본에서는 필기 시행이 10건 중 1건이었으나, **`ncsCdLst`+`hireTypeLst` 필터 적용 후에는 30건 중 절반 가까이가 필기를 시행한다.** ②는 여전히 유효하지만, 주된 효과는 트래픽 절감보다 "필기 없는 공고에 시험정보 칸을 비워두지 않는 것"에 있다.

### `/list`와 `/detail`의 차이 (중요)

**`/list` 응답의 `files`와 `steps`는 항상 빈 배열이다.** 필드는 존재하나 값이 채워지지 않는다. 첨부파일과 직렬별 모집단위(`steps[]`)를 얻으려면 반드시 `/detail`을 호출해야 한다.

또한 `/list`의 `recrutNope`는 공고 전체 인원이다(철도공사 600명). 직렬별 인원은 `steps[]`에 있다.

### 트래픽 관리: 응답 헤더 활용

```
X-RateLimit-Limit: 1000
X-RateLimit-Remaining: 995
```

**API가 잔여 호출량을 헤더로 알려준다.** Redis 카운터를 별도로 관리하지 않고 이 헤더를 파싱한다. 잔여량이 임계값(예: 100) 아래면 `/detail` 호출을 중단하고 다음 배치로 미룬다.

### 첨부파일 다운로드 차단 대응

`https://opendata.alio.go.kr/recruit/downloadAtchFile?recrutAtchFileNo=...`를 프로그램에서 직접 호출하면 PDF가 아닌 포털 홈페이지 HTML(약 8.5KB)이 반환된다. 브라우저에서는 정상 다운로드된다. 핫링크 방지로 추정된다.

**시도 순서**

1. **`Referer` 헤더 추가** — `Referer: https://opendata.alio.go.kr/`, `User-Agent: Mozilla/5.0`. 응답 `Content-Type`이 `application/pdf`면 해결.
2. **세션 쿠키 확보** — 1이 실패하면 `CookieManager`를 붙인 `HttpClient`로 메인 페이지를 먼저 호출해 세션 쿠키를 받은 뒤 파일을 요청한다. 포털이 `jquery.fileDownload.js`를 사용하는 것으로 보아 쿠키 기반일 가능성이 있다.
3. **응답 검증 필수** — 어느 경로든 다운로드 후 `Content-Type`과 매직 넘버(`%PDF`)를 확인한다. HTML을 PDF로 착각해 파싱하면 무의미한 텍스트가 LLM에 들어간다.

> **막혀도 서비스는 성립한다.** API 텍스트(`scrnprcdrMthdExpln`)만으로 필기 유무·유형·시험일, 일부 공고는 NCS 영역까지 확보된다. 첨부 파싱은 커버리지 보강 수단이다.

|---|---|
| **다중 코드** | `ncsCdLst`, `hireTypeLst`, `workRgnLst`는 콤마 구분 문자열이다 (예: `"R1010,R1070"`). 완전 일치가 아닌 부분 포함으로 매칭한다 |
| **미정의 코드** | 코드정의서 v1.2(2023)에 없는 코드가 실제로 존재한다 (`R3027 = 전남광주`). 미정의 코드를 만나면 예외를 던지지 말고 `UNKNOWN`으로 저장하고 로그만 남긴다 |
| **`srcUrl` 품질** | 공고 상세가 아닌 채용 메인 페이지인 경우가 있다 (`info.korail.com`, `comwel.or.kr/recruit/hp/main.do`). **첨부 공고문 링크를 함께 노출한다** |
| **`totalCount`** | 필터 없이 조회 시 112,655건. 병원·대학병원의 비정규직 공고가 대부분이므로 필터는 필수다 |

**게이트 판정**

| 결과 | 판단 |
|---|---|
| 텍스트 추출 8/10 이상 + LLM 정확도 70% 이상 | 계획대로 진행 |
| 텍스트 추출 5~7/10 | HWP → PDF 변환 파이프라인 추가 검토 |
| 텍스트 추출 5/10 미만 또는 LLM 정확도 50% 미만 | **설계 재검토.** 반자동(운영자 입력 보조) 방향으로 전환 |

> W0 결과는 `docs/adr/0002-extraction-feasibility.md` 로 기록한다. 이 문서가 나중에 포트폴리오에서 가장 설득력 있는 자료가 된다. **모델 비교 결과표(모델별 정확도·비용)를 반드시 포함한다.**

### 외부 지원 프로그램 활용 (선택)

과기정통부 '모두의 AI 실험실'(aitestbed.kr)에서 AI 토큰과 다중 모델 이용을 무상 제공한다. 활용 방침은 다음과 같다.

| 항목 | 활용 |
|---|---|
| AI 토큰 / 생성형 AI 모델 | **활용.** W0 모델 비교와 W3 프롬프트 반복 실험에 사용 |
| 공공·민간 데이터 / API | 목록만 확인. 기대치는 낮게 |
| 민간 클라우드 | 실험용 샌드박스로만. **배포 인프라로 쓰지 않는다** |
| Grafana (개발지원도구) | **활용.** W6 지표 대시보드. 종료 대비는 아래 참조 |
| GPU | **사용하지 않는다.** 모델 학습이나 자체 서빙을 하지 않으므로 불필요 |
| 바이브코딩 환경 | 사용하지 않는다. 스택과 명세가 확정되어 있고, 직접 구현이 목적이다 |

> **배포 인프라를 지원 클라우드에 얹지 않는 이유**: 지원 기간 종료 시 공개 운영 중인 서비스를 마이그레이션해야 한다. 이용자가 붙은 뒤의 인프라 이전은 리스크가 크다. 배포는 자체 VPS로 유지한다.
>
> 신청 전 **지식재산권 귀속, 성과 공유 의무, 지원 기간**을 확인한다.

**지원 기간 3개월 종료 대비**

| 항목 | 종료 시 영향 | 대비 |
|---|---|---|
| Grafana | **낮음.** 데이터는 우리 MySQL에 있고 Grafana는 조회 도구일 뿐 | 대시보드 JSON을 저장소에 커밋해두면 자체 서버에 컨테이너로 재기동 가능(오픈소스·무료) |
| AI 토큰 | 보통 | 실험 구간(W0·W3)이 3개월 안에 끝난다. 운영 단계 호출량은 월 수천 원 수준 |
| 민간 클라우드 | 해당 없음 | 처음부터 배포에 쓰지 않는다 |

> **종료 전에 대시보드 스크린샷과 지표 스냅샷을 확보한다.** 포트폴리오 자료이자 지표 시계열의 백업이다.

## W1 — 기반 + 수집

**산출물**: 데이터가 DB에 쌓인다. 화면은 없다.

- 프로젝트 셋업 (Spring Boot, Docker Compose, Flyway, GitHub Actions)
- 도메인 엔티티 + 마이그레이션 (`INSTITUTION` ~ `CLICK_EVENT` 전체)
- Collector 구현: API 폴링, `content_hash` 중복 차단, `RECRUITMENT`/`POSITION` 저장
- `COLLECTION_BATCH_LOG` 기록
- 텔레그램 알림 (배치 실패 시)
- **`R1030`(무기계약직) 필기 시행 비율 확인** → 수집 대상 포함 여부 결정
- GitHub Issues / Projects 보드 세팅

**완료 기준**: 배치를 돌리면 전산·행정 공고가 DB에 저장되고, 두 번 돌려도 중복이 생기지 않는다.

## W2 — 최소 배포 ⭐ v0.1

**산출물**: 실제 URL에서 접속 가능한 서비스. **시험 정보는 아직 없다.**

- `GET /recruitments` (필터: 직렬, 고용유형, 상태 / 정렬: 마감임박순)
- `GET /meta/health`
- React 목록 화면 — 기관명, 제목, 접수기간, D-day, 원문 링크
- **OG 메타태그** (공고 상세) — 링크 공유 시 카드 프리뷰. 배포 시점부터 있어야 유입에 기여한다
- 푸터: 출처 표기 + 면책 문구
- **배포**: 도메인 연결, Nginx + HTTPS, Docker Compose 기동

**완료 기준**: 남에게 URL을 보낼 수 있다.

> 이 시점부터 본인이 매일 사용한다. 뭐가 불편한지는 써봐야만 안다.

## W3 — 추출 파이프라인

**산출물**: LLM이 시험 정보를 뽑아 DB에 넣는다. 아직 화면에는 안 나온다.

- 첨부파일 다운로드 + 텍스트 추출 (PDFBox, hwplib, hwpxlib)
- LLM 추출 서비스: 프롬프트 + JSON 스키마 강제 + NCS 영역 Enum 정규화
- confidence 산출 로직 + 자동 승인 임계값
- `EXTRACTION_LOG` 기록 (소요시간, confidence, 성공 여부)
- 추출 실패 시 `UNCERTAIN` 처리

**완료 기준**: 공고 20건을 처리했을 때 자동 승인 / 검수 대기 / 실패로 분류된다. **이때의 자동 승인률을 기록한다. 이 숫자가 개선 지표의 시작점(before)이다.**

## 이후 (운영 단계)

배포 이후가 진짜다. 정해진 주차는 없고 **격주 단위로 하나씩** 처리한다.

| 우선순위 | 항목 | 비고 |
|---|---|---|
| 높음 | 프롬프트 개선 → 자동 승인률 추적 | before/after 반드시 기록 |
| 높음 | **정보 오류 신고 기능** | 공고 ID + 오류 필드 + 한 줄 설명. 개인정보 없음. 추출 정확도를 사용자가 검증해주는 채널 |
| 높음 | HWP 파싱 실패 케이스 분석 | 실패율 30% 초과 시 변환 파이프라인 검토 |
| 보통 | 필터 사용 데이터 기반 UI 개선 | 어떤 필터가 많이 쓰이는지 |
| 보통 | **누락 공고 제보 기능** | 원문 URL 하나만 수집. 제보 건수 = 커버리지 지표 |
| 보통 | 직렬 확장 (기계, 전기) | |
| 보통 | **고용유형 확장 (계약직·체험형 인턴 등)** | `hireTypeLst`에 코드 추가만 하면 됨. 스키마 변경 불필요. **단, 기본 필터는 정규직+채용형인턴으로 유지**하고 "전체 보기" 선택 시에만 노출 |
| 보통 | 마크다운 복사 버튼 | 공고 상세 → 클립보드. 노션 붙여넣기용 |
| 낮음 | 스크랩 + 노션 OAuth 연동 | **로그인이 전제됨.** CSV 사용량·클릭 데이터로 수요 확인 후 판단 |
| 낮음 | 보조 소스 추가 / 다중 소스 병합 | 중복 제거 전략을 ADR로 먼저 결정 |
| 낮음 | 행정안전부 지방공공기관 소스 편입 | 첨부파일이 없어 시험정보는 못 채움 |

## 일정 관리 방식

**GitHub Projects (칸반) + Milestones + Issues** 조합으로 관리한다. 별도 도구는 쓰지 않는다.

- **Milestone** = 위 주차 (`W1 기반+수집`, `W2 최소배포` …). 각 주차의 완료 기준을 milestone 설명에 그대로 넣는다.
- **Issue** = 작업 단위. 반나절~하루 안에 끝나는 크기로 자른다. 제목은 `[W3] HWP 텍스트 추출기 구현` 형식.
- **Label** = `type:feat` `type:fix` `type:docs` / `area:collector` `area:extractor` `area:frontend` `area:infra` / `priority:high`
- **Board 컬럼** = `Backlog` → `This Week` → `In Progress` → `Review` → `Done`
- **규칙**: `In Progress`에는 항상 이슈 1개만 둔다. 동시에 여러 개를 벌리지 않는다.
- 커밋 메시지에 `#이슈번호`를 넣어 자동 연결한다.

포트폴리오 관점에서, 이슈 트래킹 기록 자체가 "체계적으로 일했다"는 증거가 된다. 나중에 급하게 만들 수 없으므로 W1부터 지킨다.
