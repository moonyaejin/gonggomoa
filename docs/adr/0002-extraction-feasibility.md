# ADR-0002: 시험 정보 추출 파이프라인 실현 가능성 검증 (W0 스파이크)

- 상태: 채택
- 날짜: 2026-08-07
- 관련: ADR-0003(직렬 단위 저장), `docs/05-roadmap.md`

## 배경

이 서비스의 존재 이유는 공기업 채용공고의 **필기시험 구성 정보를 구조화해 필터링 가능하게 만드는 것**이다. 이 정보는 공공데이터 API의 정형 필드에 존재하지 않으며, 공고 첨부파일(HWP/PDF) 내부에만 있을 것으로 예상되었다.

따라서 착수 전 다음을 검증해야 했다.

1. 공공데이터 API로 대상 공고를 정확히 수집할 수 있는가
2. 시험 정보를 어디서, 어느 수준까지 얻을 수 있는가
3. 얻은 정보를 우리 도메인 모델(직렬 단위)에 매핑할 수 있는가

**최대 리스크로 지목한 것은 HWP 파싱이었다.** 구형 바이너리 포맷의 파싱 실패율이 높으면 서비스 컨셉 자체가 성립하지 않는다고 판단했다.

## 검증 방법

재정경제부 공공기관 채용정보 조회서비스(`/list`, `/detail`)를 실제 호출하고, 반환된 공고와 첨부파일을 수동으로 분석했다. 표본은 접수중 공고 전수(30건)와 개별 상세 조회 건이다.

## 검증 결과

### 1. 수집 필터 — 확정

| 파라미터 조합 | totalCount |
|---|---|
| `ongoingYn=Y` 만 | 607 |
| `+ ncsCdLst=R600020,R600002 + hireTypeLst=R1010,R1070` | **30** |
| `+ instType=A2001,A2002,A2003,A2004` | 0 (다중값 미지원) |
| `+ instType=A2001` (단일값) | 2 |

- `instType`은 **콤마 다중값을 지원하지 않는다.** 기관유형 4개를 각각 호출해 병합한다.
- `ncsCdLst`, `hireTypeLst`는 다중값이 동작한다. 다만 파라미터별로 동작이 다르므로 어댑터에 단일값 반복 호출 폴백 경로를 둔다.
- **운영 규모는 접수중 30건 수준.** 일 신규는 수 건. 일일 1,000건 한도에 여유가 크다.

### 2. 시험 정보 확보 경로 — 예상과 달랐다

**`scrnprcdrMthdExpln`(전형절차 설명) 필드가 핵심 소스로 드러났다.** 당초 첨부파일에만 있을 것으로 본 정보가 상당 부분 이 텍스트 필드에 들어 있다.

| 기관 | API 텍스트에서 확보되는 것 |
|---|---|
| 한국중부발전 | `문항수: 60문항 / 평가요소 : 의사소통능력, 문제해결능력, 직업윤리` → **NCS 세부 영역까지** |
| 한국보훈복지의료공단 | `NCS 직업기초능력평가(40), 직무수행능력평가(50), 한국사(10)` → 유형 + 배점 |
| 한국산업안전보건공단 | `필기전형 : 2026. 10. 17.(토) 예정, 4배수 선발` → **필기시험일** |
| 한국철도공사 | `직업기초능력평가(30문항), 직무수행능력평가(30문항), 철도법령(10문항)` |
| 근로복지공단 | `NCS직업기초능력, NCS 직무기초지식` + 전산직 코딩테스트 면접 |

첨부 공고문(`atchFileType=A`)에는 오히려 NCS 세부 영역이 없는 경우가 있었다. 한국철도공사 공고문은 "필기시험 세부사항은 [참고7]에서 확인"이라고만 하며, 실제 영역 정보는 `atchFileType=Z`(참고자료)에 있다.

### 3. 첨부파일 다운로드 — 차단됨 (미해결)

`opendata.alio.go.kr/recruit/downloadAtchFile` 직접 호출 시 PDF가 아닌 포털 홈페이지 HTML(8,511바이트)이 반환된다. `Referer`, `User-Agent` 헤더를 추가해도 동일하다. 브라우저에서는 정상 다운로드된다.

포털이 `jquery.fileDownload.js`를 사용하는 점, 응답이 항상 동일한 메인 페이지인 점으로 보아 **세션 쿠키 기반 접근 제어**로 판단한다. W3에서 `CookieManager`를 붙인 `HttpClient`로 세션을 먼저 확보한 뒤 요청하는 방식으로 처리한다.

### 4. 직렬 매핑 — 부분적 한계 확인

- `/detail`의 `steps[]`에 실제 모집단위명이 들어온다(`전기통신(공개경쟁채용)` 등). `POSITION.raw_position_name`을 채울 수 있다.
- 단, `steps[]`는 **모집단위 × 전형단계로 3행씩 중복**되므로 `sortNo` 그룹핑이 필요하다.
- `steps[].recrutNope`는 항상 `null`이다. **직렬별 인원은 API로 얻을 수 없다.**
- **NCS 대분류 오분류가 실증되었다.** 한국철도공사 공고에 `R600020 정보통신`이 태깅되어 있으나 실제 모집단위 11개 중 전산직은 없다. `전기통신`은 전기·신호 설비 직무다.

## 결정

**게이트 통과. 계획대로 진행하되 세 가지를 조정한다.**

### 결정 1 — 추출 소스의 우선순위를 뒤집는다

당초: 첨부파일 파싱이 주 경로, API 텍스트는 보조
변경: **API 텍스트(`scrnprcdrMthdExpln`)가 주 경로, 첨부파일은 커버리지 보강**

→ **HWP 파싱이 W0 최대 리스크에서 선택적 과제로 내려간다.** 첨부 다운로드가 끝내 막히더라도 서비스는 성립한다.

### 결정 2 — 첨부파일 대상에 `Z`(기타)를 포함한다

NCS 세부 영역이 공고문(`A`)이 아닌 참고자료(`Z`)에 있는 사례가 확인되었다. `Z`에는 자기소개서 등 무관한 파일도 섞이므로 파일명 휴리스틱(`참고`, `세부`, `별첨`)으로 선별한다.

### 결정 3 — 핵심 가치 순위를 재정의한다

NCS 세부 영역은 100% 확보가 불가능하다. 따라서 가치를 다음 순서로 정의한다.

1. 필기전형 유무 (확보 용이)
2. 시험 유형 — NCS만 / NCS+전공 (확보 용이)
3. 필기시험일 (부분 확보)
4. NCS 세부 영역 (일부 확보)

**1~3만으로도 기존 서비스에 없는 가치다.** 잡알리오는 필기시험일을 구조화해 제공하지 않는다. 확보하지 못한 항목은 필드 단위로 "공고문 직접 확인 필요"를 표시하고 원문 링크를 함께 제공한다.

## 결과

**긍정**
- 최대 리스크(HWP 파싱)가 제거되었다. W3 일정 부담이 줄었다.
- 수집 대상이 30건 수준으로 확정되어 검수 부담과 트래픽 우려가 해소되었다.
- 필터 파라미터가 실호출로 검증되어 W1 착수에 필요한 정보가 모두 확보되었다.

**부정**
- 직렬별 채용인원을 API로 얻을 수 없어 공고문 파싱에 의존한다.
- NCS 대분류 필터의 정밀도가 낮아 무관한 공고가 노출된다. `raw_position_name` 병기로 완화하되 완전한 해결은 아니다.
- 첨부파일 다운로드가 미해결 상태로 W3에 이월된다.

**측정 시작점 (before)**

이후 개선을 추적하기 위한 초기 수치를 기록한다.

| 항목 | W0 시점 |
|---|---|
| 수집 대상 공고 (접수중) | 30건 |
| 표본 중 필기 시행 비율 | 필터 적용 전 약 10% → 적용 후 약 50% |
| API 텍스트만으로 시험 유형 확보 | 확인된 필기 시행 공고 전부 |
| API 텍스트만으로 NCS 영역 확보 | 일부 (중부발전 등) |
| 첨부파일 다운로드 성공률 | 0% (세션 차단) |
| 자동 승인률 | 미측정 (W3에서 최초 측정) |

## 대안 검토

**인사혁신처_공공취업정보 API** — 목록에 접수시작일·직렬·원문URL이 없고 용어 체계가 공무원 중심이어서 제외했다.

**행정안전부_지방공공기관 채용정보 API** — 상세조회와 첨부파일 엔드포인트가 없어 시험 정보 추출이 불가능하다. v1.1 이후 커버리지 보강용으로만 검토한다.

**잡알리오 웹사이트 크롤링** — 공식 API가 동일 데이터를 제공하므로 채택하지 않는다. HTML 구조 변경에 취약하고 상대 서버에 불필요한 부하를 준다.

**기관정보 오픈API로 기관 마스터 구축 후 애플리케이션 필터링** — `instType` 다중값 미지원의 우회책으로 검토했으나, 단일값 4회 호출로 충분함이 확인되어 불필요해졌다.
