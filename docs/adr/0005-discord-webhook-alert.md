# ADR-0005: 배치 실패 알림을 텔레그램 봇 대신 디스코드 웹훅으로 구현

- 상태: 채택
- 날짜: 2026-09-14
- 관련: `docs/01-requirements.md` FR-6.4, `docs/04-architecture.md` §6(장애 시 동작)

## 배경

`docs/05-roadmap.md` W1 범위에 "배치 실패 시 텔레그램 알림"이 있었고, CLAUDE.md
고정 인프라 스택에도 "텔레그램 봇 알림"으로 명시돼 있었다. 실제 구현 시점에
텔레그램은 봇 생성(BotFather) · chat_id 확보 등 사전 설정이 필요한 반면, 1인
운영 규모에서는 그 절차 대비 얻는 이점이 크지 않다고 판단했다.

## 결정

**디스코드 웹훅으로 구현한다.** 채널에서 웹훅 URL만 발급하면 되고 봇 생성이
필요 없다. 알림이 채널에 히스토리로 쌓여 추적하기도 텔레그램보다 편하다.

## 근거 / 대안 비교

| 방식 | 사전 설정 | 이력 추적 | 채택 |
|---|---|---|---|
| 텔레그램 봇 | BotFather로 봇 생성 + chat_id 확보 | 봇과의 1:1 대화 기록 | ❌ |
| **디스코드 웹훅** | 채널에서 웹훅 URL 발급 (봇 불필요) | 채널에 메시지로 누적, 검색·스크롤 용이 | ✅ |

## 설계

- `DISCORD_WEBHOOK_URL` 환경변수 하나로 동작. 봇 토큰·채널 ID 같은 부가 설정 없음.
- 트리거는 `COLLECTION_BATCH_LOG`에 실패가 기록되는 시점. FR-6.4가 요구하는
  건 "연속 실패"이므로, 매 실패마다 보내지 않고 최근 로그를 조회해 **연속
  실패 횟수가 임계값(기본 3회)에 처음 도달한 시점에만** 발송한다. 이후
  같은 연속 실패가 계속돼도 매번 재발송하지 않는다 — 스팸 방지가 목적이므로
  "이미 알렸다"는 사실 자체가 새 정보를 주지 않는다. 임계값은
  설정값(`gonggomoa.collector.discord-alert.failure-threshold`)으로 뺀다.
- 알림 발송은 배치의 핵심 경로가 아니다. 발송 실패(웹훅 URL 오류, 디스코드
  장애 등)가 배치 자체를 실패시키거나 예외를 전파해선 안 되므로, 알림
  컴포넌트 내부에서 모든 예외를 잡아 로그만 남기고 삼킨다.
- 웹훅 URL은 그 자체가 인증 정보다(아는 사람 누구나 그 채널에 메시지를
  보낼 수 있음). 요청 로그에 URL을 남기지 않는다 — MOEF `serviceKey` 마스킹과
  같은 이유.

## 결과

- 긍정: 봇 생성 없이 환경변수 하나로 알림 채널 구성 가능. 운영 부담 감소
- 긍정: 채널 히스토리 자체가 배치 실패 이력이 되어 별도 조회 없이 추적 가능
- 부정: 디스코드 계정/서버가 없으면 여전히 서버 하나는 만들어야 함 (텔레그램도
  마찬가지로 계정은 필요해 상대적 단점은 아님)
